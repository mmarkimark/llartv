# LlarTV v1.6 performance (emulator and reference TV, paired)

**Status: the emulator and the reference-TV paired checks are inside every allowance.** v1.6 adds a quote of the day,
the weather place and source, and a minimal mode. The emulator numbers are a regression guard; the reference-TV pair
is the release gate (see [the targets](baseline-v1.0.md#targets)).

## Setup

- Target: Android TV emulator `emulator-5554`, AOSP TV on x86, Android 11 (SDK 30), same fixture for both versions
  (Bing wallpaper, default dock, Catalan interface); the configuration was written again after every install.
- Baseline: [published v1.5 APK](https://github.com/mmarkimark/llartv/releases/download/v1.5/LlarTV.apk),
  4,149,623 bytes.
- Candidate: the release APK, debug, built from `main` (`49ae76b`) in a clean worktree, 4,266,913 bytes
  (+117,290 bytes, +2.83%; the three quote files add about 351 KB of text), same signing certificate, installed in
  place with `install -r -d`. An earlier incremental build of the same tree measured 4,326,621 bytes: 60 KB of stale
  dex, not a real change.
- Procedure: `scripts/measure.sh --serial emulator-5554 --apk <apk> --runs 5` (one discarded warm-up, five cold
  starts, five returns from another app, three PSS samples), after a 20 s settle following each install. Two
  alternating rounds: baseline, candidate, baseline, candidate.

## Reference TV

Xiaomi MiTV-MSSP3, Android 11/API30, the owner's own configuration (written again after every install and restored
byte for byte at the end). The same two APKs, installed in place with `install -r -d` (no uninstall and no data
wipe): the [published v1.5](https://github.com/mmarkimark/llartv/releases/download/v1.5/LlarTV.apk) (4,149,623
bytes, sha256 `8ac6d9be…`, the exact APK the TV was running before the check) and the v1.6 release candidate
(4,266,913 bytes, sha256 `d69e594f…`), same signing certificate. `scripts/measure.sh --serial <tv> --apk <apk>
--runs 7` (one discarded warm-up, seven cold starts, seven returns from another app, three PSS samples), five pairs
in an order-balanced sequence: v1.6 first, v1.5 first, v1.6 first, v1.5 first, v1.6 first. The order is balanced
because the reading taken first after an install is the one the state of the device can favour.

allowance under both readings.

### Two readings that needed explaining

- **A first pair read +5,408 KB of RAM.** That was the wallpaper bitmap, not the app: `dumpsys meminfo` taken in the
  same state shows the `GL mtrack` category at 8,060 KB in one round and 13,512 KB in the next, for both versions, so
  that pair happened to measure v1.6 with the larger bitmap resident. The order-balanced sample above, with the
  category breakdown kept next to every reading, is the one the release rests on.
- **The cold start of v1.6 has a slower tail.** 14 of its 35 samples are above 1,500 ms against 2 of 35 for v1.5,
  which looks like the quote file being read at Home start. Measuring the same APK with only `quote=on` and
  `quote=off` changed (28 samples each, four order-balanced rounds) says otherwise: the median cold start is
  1,374 ms with the quote off and 1,402 ms with it on, so the corpus costs about 28 ms, and the same slow tail
  appears with the quote disabled. The tail is the TV's own noise, not v1.6.

### The minimal mode on the same TV

The minimal mode is a switch, not a build variant, so it was measured on the same TV with the same APK: two
order-balanced rounds of seven cold starts each, the owner's configuration apart from `minimal=on|off`.

| Metric | normal | minimal | Difference | What it means |
| --- | --- | --- | --- | --- |
| Cold start, median ms | 1,555 | 1,095 | −460 ms (−29.6%) | Home appears almost a third faster |
| Home return, median ms | 259 | 192 | −66 ms (−25.7%) | Coming back to Home is quicker too |
| RAM, TOTAL PSS, median KB | 59,750 | 43,100 | −16,650 KB (−27.9%) | About 16 MB less in memory |

## Release

The published APK is the one built from `main` (`49ae76b`) in a clean worktree: 4,266,913 bytes, sha256
`d69e594f8f40098429053881b25e594454ac318e5da1858aee87369c20cc89a3`, versionCode 7, the same certificate as v1.5,

matched.

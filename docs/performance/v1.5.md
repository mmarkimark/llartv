# LlarTV v1.5 performance (emulator, paired)

**Status: emulator paired check inside the paired allowances; the reference-TV gate is still open.** The TVs were in
use during v1.5 development, so no physical-TV numbers exist yet. Emulator numbers are a regression guard, not a
substitute for the [physical-TV release gate](baseline-v1.0.md#targets).

## Setup

- Target: Android TV emulator `emulator-5554`, AOSP TV on x86, Android 11 (SDK 30). Same fixture for both versions
  (Bing wallpaper, default dock, Catalan interface); the owner's configuration was restored after each check.
- Baseline: [published v1.4 APK](https://github.com/mmarkimark/llartv/releases/download/v1.4/LlarTV.apk),
  4,133,135 bytes, debuggable.
- Candidate: feature branch through `f467a95` (#36, #39, #38, #37), debug APK, 4,227,211 bytes, debuggable, same
  signing identity (installed in place with `install -r -d`, no uninstall or data wipe).
- Procedure: `scripts/measure.sh --serial emulator-5554 --apk <apk> --runs 7` (one discarded warm-up, seven cold
  starts, seven returns from another app, three PSS samples), after a 20 s settle following each install. Two
  rounds in alternating order: candidate, baseline, candidate, baseline.

## Results

| Metric | v1.4 round a | v1.4 round b | v1.5 round a | v1.5 round b | Difference (medians of the rounds) | Paired allowance | Result |
| --- | --- | --- | --- | --- | --- | --- | --- |
| APK bytes | 4,133,135 | | 4,227,211 | | +94,076 (+2.28%) | +5% | Inside |
| Cold start, median ms | 539 | 524 | 571 | 561 | +35 ms (+6.6%) | +150 ms and +15% | Inside |
| Home return, median ms | 87 | 93 | 94 | 83 | −2 ms | +40 ms and +40% | Inside |
| RAM, TOTAL PSS, median KB | 40,106 | 40,080 | 40,041 | 40,097 | −24 KB | +4,096 KB and +10% | Inside |

A first, single-order run (each version measured once, five runs, straight after install) gave a v1.5 cold-start
median of 1645 ms with a 722–2947 ms spread, against 561 ms for v1.4. The alternating repeat above, with a settle
period, did not reproduce it (all fourteen v1.5 cold starts were 504–596 ms), so it is recorded as an unexplained
emulator outlier, not as a result either way.

As in [v1.4](v1.4.md), this follows the policy of comparing with the previous version on the same running target.
No historical absolute-limit pass is asserted: the APK is above the v1.0-based emulator limit of 4,199,617 bytes
(the v1.0 baseline +5%), which v1.4 already approached; that cumulative growth is open for the owner to judge
before release.

# v1.4 candidate: emulator and reference-TV performance

**Controlled reference-TV regression checks passed.** The owner-authorized equivalent-install comparison below
is within every paired allowance; the initial over-budget capture remains recorded with its unresolved cause.
Emulator evidence is separate, not a substitute for the [physical-TV release gate](baseline-v1.0.md#targets).
Final delivery and public asset transport remain pending.
Real-TV music lifecycle checks passed and the owner confirmed audible distinct tracks; public asset transport remains unverified.
The historical baselines and budgets are unchanged.

## Method

- Date: 2026-10-31. Target: AVD `tv11`, AOSP TV x86, Android 11/API 30, headless with software rendering.
- Baseline: actual [published v1.3 APK](https://github.com/mmarkimark/llartv/releases/download/v1.3/LlarTV.apk),
  4,050,747 bytes; SHA-256 `72c77bcd77bbbc727a8ebca23613ea0d815fb0cbda7fab84c1309d5ec0d885e7`.
- Candidate: source through `4c9e464`, with local `versionName=1.4` / `versionCode=5` metadata; debug APK,
  4,133,135 bytes. Matching signing identities checked before an in-place downgrade; no uninstall/data wipe.
- Same running emulator and identical configuration: plain background, weather/news/music off, morning/night off,
  24-hour clock, same four installed dock apps. Baseline measured first, candidate second.
- Existing `scripts/measure.sh`: one discarded warm-up, five cold starts and five returns from another app,
  three foreground `TOTAL PSS` samples. Both return measurements used **explicit activity resume**, not HOME intent.
- Afterwards: candidate 1.4/code5, original configuration, Android settings and original default home restored and
  read back. No physical TV was changed.

```sh
./scripts/measure.sh --serial emulator-5554 --apk <installed-apk> \
  --runs 5 --label '<version> Android11 emulator' --out <report>
```

## Paired results

| Metric | Published v1.3 | Candidate v1.4 | Difference |
| --- | --- | --- | --- |
| APK bytes | 4,050,747 | 4,133,135 | +82,388 (+2.03%) |
| Cold start median | 2,900 ms | 2,566 ms | -334 ms (-11.52%) |
| Explicit-resume median | 167 ms | 99 ms | -68 ms (-40.72%) |
| Foreground PSS median | 35,265 KB | 35,801 KB | +536 KB (+1.52%) |

These paired changes are within the corresponding regression allowances. Five variable software-rendered runs do
not establish a reliable speedup. Both cold-start medians are slower than the old 1,384 ms emulator reference;
that historical absolute threshold is **not** claimed to pass. Emulator values do not replace TV measurements.

## Reference TV: initial paired capture

Measured on 2026-10-31, Xiaomi MiTV-MSSP3, Android 11/API30, `armeabi-v7a`. The installed v1.3 APK exactly
matched the published size/hash above. Both APKs are debuggable, with matching signing identities. Candidate
1.4/code5 was installed in place; no uninstall, data wipe, reset or change to the owner's configuration.
The same five-latency/three-PSS procedure used **HOME intent**, not explicit resume and not a human physical-button test.

| Metric | Installed published v1.3 | Candidate v1.4 | Difference |

| --- | --- | --- |
| Cold start, ms | 1130, 1087, 1093, 1084, 1059 | 1335, 1609, 1341, 1429, 1361 |
| HOME-intent return, ms | 742, 256, 257, 263, 261 | 620, 186, 180, 170, 190 |
| PSS, KB | 55848, 57473, 57400 | 62756, 64738, 64710 |

**The initial capture alone did not pass the performance gate.** Its cold-start and PSS deltas exceed both their
absolute and percentage allowances. PSS also exceeds the historical TV reference allowance. No budget was lowered.
A single bounded read-only source comparison found no evidenced material cause or justified code correction.
The long-installed baseline and freshly installed candidate had unrecorded compilation/profile state, so this
sample does not establish causality. No speculative optimization has been made. The owner subsequently authorized
exactly one controlled1.4→1.3→1.4 comparison, with equivalent reinstalls and compiler-state capture, recorded below.
No compilation filter, saved profile, data or budget was forcibly changed.

Afterwards, candidate1.4/code5 remained installed; original configuration, default Home, selected/enabled dream,
network, ADB, clock, locale and timezone were read back unchanged. Original APK/config/internal-file backups are
private and ignored, as are raw device reports; the owner's configuration and photos are not publication artifacts.

## Owner-authorized controlled reference-TV comparison

One additional bounded experiment, completed without retries: reinstall1.4, reinstall the exact published1.3, then
reinstall1.4 again, all in place with the original configuration preserved. Before and after each cohort the
reported compiler filter was `run-from-apk` (reason `unknown`): six matching observations. No compiler filter was
forced and no profiles/data were cleared. Each cohort used five cold/HOME-intent samples and three foreground PSS
samples, with the same existing procedure. Both1.4 cohorts are compared independently with the middle1.3 cohort.

| Metric | v1.4 first | Fresh v1.3 | v1.4 last | Candidate difference vs fresh v1.3 |
| --- | --- | --- | --- | --- |
| Cold start median | 1,395 ms | 1,294 ms | 1,339 ms | +101/+45 ms (+7.81%/+3.48%) |
| HOME-intent return median | 175 ms | 186 ms | 191 ms | -11/+5 ms (-5.91%/+2.69%) |
| Foreground PSS median | 64,278 KB | 64,093 KB | 64,262 KB | +185/+169 KB (+0.29%/+0.26%) |

| Raw metric | v1.4 first | Fresh v1.3 | v1.4 last |
| --- | --- | --- | --- |
| Cold start, ms | 1578, 1602, 1308, 1306, 1395 | 1294, 1292, 1332, 1293, 1362 | 1339, 1595, 2057, 1315, 1334 |
| HOME-intent return, ms | 621, 185, 171, 165, 175 | 597, 186, 170, 189, 169 | 656, 191, 186, 176, 199 |
| PSS, KB | 62385, 64310, 64278 | 62081, 64129, 64093 | 62377, 64298, 64262 |

Both candidate cohorts satisfy the absolute **and** percentage paired allowances for all three metrics; APK+2.03%
is within+5%. This follows the baseline policy's comparison with the previous version measured on the same running
target, rather than silently replacing budgets with values from different conditions. No historical absolute-limit
pass is asserted. The initial1.3 compiler state was not captured, so the exact cause of the first gap remains unknown:
there was no source-code performance fix and no claim that compilation alone caused it. The large initial gap did
not recur with these matched observations. Final1.4/code5 and all original configuration/Android/home/network/ADB/
clock/locale/timezone settings were verified again. The owner separately confirmed hearing distinct tracks.
